1. 귀사의 무궁한 발전을 기원합니다.

2. 관련
   - 가. 당사 공문 「AI 작업 통제 서비스 도입 검토 결과 통보 및 기능·자료·계약 조건 요청」 (경영지원-구매 제2026-0412호, 2026. 11. 6.(금))
   - 나. 귀사 보완 설명 1 「실행기 성격」 (실행기는 ① Plan 해시 자체 생성·Ed25519 서명·nonce 검증의 서명 검증기, ② 승인 envelope을 비대칭키 종단간 암호화(E2EE)로 받아 실행기 공개키로만 복호화하는 복호화 컴포넌트, ③ 검증 6단계 통과 시 웹쉘 세션으로 로컬 작업을 수행하는 경량 컴포넌트)
   - 다. 귀사 보완 설명 2 「Tailscale 성격」 (Tailscale은 개발·테스트 단계 임시 구성이며, 운영 배포는 고객사 내부망 연결로 웹 서비스↔실행기 mTLS, 내부망 대역은 관리자가 설정)
   - 라. 당사 내부 보완 설명 검토 회의 (2026. 11. 11.(수), 구매팀·IT운영보안팀)

3. 결론

   당사는 귀사 보완 설명 2건을 **검토 접수**합니다. 두 설명으로 당사 우려의 **성격**이 일부 바뀌었으나, 2026. 11. 6.(금) 공문(제2026-0412호) 5항 가.의 **필수 조건 5개와 붙임 2 필수 조건 검수 시험표는 변경 없이 그대로 유지**합니다. 설명은 파일럿 또는 서면 확인을 면제하는 사유가 아닙니다.
   본 공문은 제2026-0412호를 대체하지 않으며, 실행기 성격과 Tailscale 관련 항목의 **변경분만** 기재합니다. 아래 명시가 없는 항목(필수 조건, 검수 시험표, 야간 장애 지원 요구안, 계약 조건, 제출 요청 자료)은 제2026-0412호가 그대로 유효합니다.

4. 검토 결과

   **가. 보완 설명 1(실행기 성격) 수용 결과**

   당사는 실행기를 "무거운 별도 인프라 러너"가 아니라 "서명 검증기 + E2EE 복호화 + 웹쉘 세션의 경량 컴포넌트"로 재기술함을 접수하였습니다. 다만 "경량"은 서버 사양 산정에만 적용하며, 가용성 요구를 낮추는 근거로 보지 않습니다.

   | 번호 | 실행기 역할 (귀사 설명) | 명세 근거 | 당사 재평가 |
   | --- | --- | --- | --- |
   | 1 | Plan 해시를 실행기가 자체 생성(JCS 정규화 + SHA-256)하고 Ed25519 서명·nonce를 검증하는 서명 검증기 | 2.3, 5.1 | 제2026-0412호 도입 사유 1·2번의 근거가 명확해짐. 웹 서비스 해시를 쓰지 않음을 재확인 |
   | 2 | 승인 envelope을 E2EE로 받아 실행기 공개키로만 복호화, 웹 서비스는 열지 못함 | 2.4, 4.5 | 제2026-0412호 필수 조건 5번(승인받은 내용만 반영) 방향과 일치. 파일럿 변조·재사용 시험으로 실제 확인(붙임 2의 5·6번) |
   | 3 | 검증 6단계 통과 시 웹쉘 세션으로 로컬 작업 수행하는 경량 컴포넌트 | 5장 | 성격 재기술 접수. "경량"은 서버 사양에만 적용, 24시간 물류센터 가용성 요구는 유지 |

   **나. 보완 설명 2(Tailscale) 수용 결과**

   당사는 Tailscale이 개발·테스트 단계 임시 구성이며 운영 배포는 사내 내부망 mTLS임을 접수하였습니다. 이로써 "외부 조정 서버 상시 통신"이라는 당사 보안 심의 쟁점이 완화되었으나, 보안 심의 대상 자체가 "내부망 mTLS 구성·내부망 대역 설정·테스트 구성 잔존 여부"로 **이동**한 것으로 봅니다.

   **다. 완화 항목과 잔존 조건 구분**

   아래 표는 제2026-0412호 4항 다.(우려 사항)와 5항(요청 사항)의 해당 항목을 보완 설명에 따라 재분류한 것입니다.

   | 제2026-0412호 항목 | 귀사 설명 | 당사 재평가 | 구분 |
   | --- | --- | --- | --- |
   | 4-다-4 실행기 단일 구성 | 경량 컴포넌트 | 성격은 재기술되나, 컴포넌트 1개 장애 시 6개 센터 긴급 변경 정지 위험은 그대로 | **잔존** (가용성 요구 유지, 5항 가.로 재요청) |
   | 4-다-5 Tailscale 신규 도입·조정 서버 외부 소재 | 개발 test용, 운영은 내부망 mTLS | 외부 조정 서버 상시 통신 쟁점 완화 | **완화** |
   | 5-가-5 / 4-다-5 test 구성 잔존 | 운영 전환 시 Tailscale 미사용 | 운영 전환 시 test용 Tailscale 클라이언트·키·라우팅 제거 증빙 필요 | **잔존** (설치 절차서로 확인) |
   | 5-가-4 SSL VPN 내부망 판별 | 회사 VPN/전용회선(MPLS) 대역을 내부망으로 등록 가능 | "등록 가능"이 당사 경로의 실제 `INTERNAL` 판별을 보장하지 않음 | **잔존** (필수 조건 4번·붙임 2의 3·4번 유지, 변경 없음) |
   | 5-가-1 envelope E2EE 복호화 | 실행기 공개키로만 복호화 | 설계 방향 일치, 파일럿 검수로 확인 | **완화** (단, 붙임 2의 5·6번 유지) |

5. 재요청 사항

   아래는 보완 설명에 따라 **제2026-0412호의 해당 요청을 갱신**한 것입니다. 번호는 제2026-0412호 요청 번호에 대응합니다. 그 외 요청은 제2026-0412호가 그대로 유효합니다.

   **가. 희망 요청 3번 갱신 — 실행기 다중화/페일오버 (기존 "실행기 2대 구성"을 대체)**

   제2026-0412호 5항 나. 3번의 "실행기 2대 구성(본사 전산실 + 이천센터)" 요구를 **실행기 컴포넌트 다중화(active-standby 또는 active-active)와 페일오버**로 재서술합니다. 물리 서버 대수는 귀사 설계에 맡기되, 아래를 서면으로 회신하여 주십시오.

   | 번호 | 확인 항목 | 요청 내용 | 기한 |
   | --- | --- | --- | --- |
   | 3-1 | 전환 방식 | 주 컴포넌트 장애 시 예비 컴포넌트로 전환하는 방식(수동/자동)과 전환 소요 시간 | 2026. 11. 20.(금) 서면 |
   | 3-2 | 상태 이전 | 실행기 공개키·개인키, 보관 Plan 해시, 사용한 nonce 소진 상태, 금지 규칙·정책 버전이 예비 컴포넌트에 동기화되는 방식 | 2026. 11. 20.(금) 서면 |
   | 3-3 | 중복 실행 방지 | 전환 중 동일 승인 envelope이 양 컴포넌트에서 중복 실행되지 않는 방식(nonce 일원화 또는 잠금) | 2026. 11. 20.(금) 서면 |
   | 3-4 | 복호화 키 처리 | envelope이 실행기 공개키로만 복호화된다면, 예비 컴포넌트의 공개키를 승인 envelope 암호화 대상에 포함하는 방식(키 공유 vs 다중 수신자 암호화) | 2026. 11. 20.(금) 서면 |
   | 3-5 | 장애 중 처리 | 전환 중 제출·승인 요청이 `502 EXECUTOR_UNAVAILABLE`로 상태 유지되는지(4.3)와 전환 후 재처리 경로 | 2026. 11. 20.(금) 서면 |
   | 3-6 | 비용 | 다중화 구성 시 구축비 1,500만 원 포함 여부, 거점 추가 시 증분 비용. **경량 컴포넌트 설명에 따른 서버 사양·구축비 조정분 반영** | 2026. 11. 20.(금) 서면 |

   - 단일 구성으로 시작하는 경우에도 가용성 요구(붙임 3)는 유지하며, 파일럿에서 주 컴포넌트를 실제 중단하여 `502 EXECUTOR_UNAVAILABLE` 상태 유지와 비상 변경 절차를 시험합니다(붙임 2의 8번). `EXECUTOR_UNAVAILABLE` 상태에서 승인 통제를 해제하고 작업하는 것은 복구로 인정하지 않습니다.

   **나. 제출 요청 자료 3번 갱신 — 실행기 구성도(개발 test·운영 배포 구분)**

   제2026-0412호 6항 3번(실행기 구성도, 외부 접속 목적지와 포트, Tailscale 조정 서버 통신 범위)을 아래로 갱신합니다.

   | 번호 | 자료 | 기한 |
   | --- | --- | --- |
   | 3-1 | **개발·테스트 구성도**: Tailscale 조정 서버와의 통신 항목·목적지·포트, 사용 범위와 사용 기간 | 2026. 11. 20.(금) |
   | 3-2 | **운영 배포 구성도**: 웹 서비스↔실행기 mTLS 구성, 인증서 발급·갱신·폐기 방식, 내부망 대역 설정 방식, 외부 접속 목적지와 포트(있는 경우) | 2026. 11. 20.(금) |
   | 3-3 | **운영 전환 절차**: 개발·테스트용 Tailscale 클라이언트·키·라우팅이 운영 전환 시 제거됨을 설치 절차서에서 증빙하는 방법(잔존 조건) | 2026. 11. 20.(금) |

   **다. 유지 항목 (변경 없음, 제2026-0412호 그대로)**

   | 번호 | 항목 | 비고 |
   | --- | --- | --- |
   | 1 | 필수 조건 5개 (제2026-0412호 5항 가.) | 설명으로 면제하지 않음. 붙임 2 검수 시험표로 확인 |
