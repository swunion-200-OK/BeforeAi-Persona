## 1. 결정 사항

### 1.1 비교 대상

| 구분 | 후보 | 비고 |
| --- | --- | --- |
| 1순위 시범 | 본 서비스 | 실행기가 Plan 해시를 직접 만들고 승인 서명을 검증하는 구조가 이번 사고 유형에 가장 맞음 (정우진) |
| 비교군 | 대형 AI 코딩 도구 + 기존 전자결재 | 같은 작업으로 "승인한 내용과 실제 실행이 연결되는지" 비교 |
| 세 번째 안 | 자체 구축 | 서재원 개발본부장이 검토 중인 안이라 품의 단계 논쟁을 막기 위해 포함 |

### 1.2 필수 통과 조건 (점수와 별도, 모든 안에 똑같이 적용)

1. 승인 없는 실행 차단
2. 감사 로그 파일 내보내기
3. 소스코드 사내 보관 (AI 분석 중 외부 전송 여부 포함)

- 하나라도 미달이면 총점과 관계없이 **도입 보류**
- 아직 구현되지 않은 기능은 "충족"으로 보지 않음. 자체 구축안은 구현·검증에 드는 비용과 기간을 적음
- 감사 로그 내보내기는 현재 API 명세에 검색 API(`GET /audit-logs`)만 있고 파일 내보내기가 없으므로 **현재 미충족**
  - 업체의 "다음 버전" 약속은 구두로 인정하지 않음. 제공 일정을 메일이나 공문으로 받음
  - **5주차 화요일까지 실제 파일을 받아 내용을 확인하지 못하면 이번 도입 후보에서 제외**
- 소스코드 사내 보관은 "실행기가 사내에 있다"는 것만으로 충족 처리하지 않음. AI 분석 단계의 데이터 흐름 자료로 확인

### 1.3 비교표 가중치

| 기준 | 기존 | 변경 |
| --- | --- | --- |
| 보안·규정 | 30% | **25%** (필수 조건이 일부 대신함) |
| 비용 | 25% | 25% |
| 업체 신뢰도 | 20% | 20% |
| 운영 부담 | 15% | 15% |
| 현업 만족도 | 10% | **15%** |

- 정우진 팀장이 처음에 비용을 20%로 내리자고 제안했으나, 최영수 본부장 보고를 고려해 비용은 유지하고 보안에서 5%포인트를 옮기기로 함
- 필수 조건으로 뺐다고 해서 보안 검증 범위를 줄이지는 않음

### 1.4 시범 사용 범위

| 항목 | 내용 |
| --- | --- |
| 참여자 | 플랫폼개발팀 6명 (절차에 불만이 있는 김태현 책임 포함) |
| 저장소 | 3개. 이력과 설정에 고객 정보·운영 접속 정보가 없는 **시범용 사본** |
| 데이터 | 합성 데이터만 사용. 실제 고객사 데이터는 넣지 않음 |
| 배포 범위 | 스테이징까지 |
| 시작 조건 | 비밀유지 계약 체결 + 한지민 과장의 데이터 흐름 검토 완료 |

### 1.5 필수 시험 항목

| 시험 | 확인할 것 | 명세 근거 |
| --- | --- | --- |
| Plan 변조 | 실행기가 `VERIFICATION_FAILED`로 거부하고 원인에 `PLAN_HASH_MISMATCH`를 남기는지 | 5.1 |
| 서명 재사용 | 같은 승인 envelope을 다시 보내면 `NONCE_ALREADY_USED`로 거부하는지 | 5.1 |
| 외부망 승인 제한 | 외부망에서 배포 승인이 `403 INTERNAL_NETWORK_ONLY`로 막히는지, 야간 당번 시나리오 포함 | 3.6, 4.4 |
| 킬 스위치 | 실행 중 외부망에서도 서명 없이 중단되는지, 반응 시간 측정 | 4.6 |
| 실행기 연결 실패 | `502 EXECUTOR_UNAVAILABLE` 때 요청 상태가 바뀌지 않는지. 연결 문제를 이유로 승인 절차를 우회하지 않음 | 4.3 |
| 처리 시간 | LOW 작업의 요청부터 실행까지 중앙값 5분 이내 | - |
| 감사 로그 내보내기 | 실제 파일을 받아 내용 확인 | 명세에 없음 |

- 대시보드(`GET /dashboard`)에는 처리 시간 통계가 없으므로, 요청·감사 기록으로 산출할 수 있는지 먼저 확인

### 1.6 현업 만족도 설문

- 운영 DB 권한 임시 회수에 대한 불만이 도구 만족도에 섞이지 않도록 분리
  - 시범 **전**: 현재 권한 제한에 대한 불편과 작업 시간을 먼저 기록
  - 시범 **종료**: 같은 작업 기준으로 승인 대기, 재승인 부담, 계속 사용할 의향을 질문
  - 권한 회수에 대한 의견은 별도 문항으로 받음

### 1.7 일정

| 시점 | 내용 |
| --- | --- |
| 3주차 월요일 | 정우진: 실행기 준비표, 서버 비용, 자체 구축 3년 비용 초안 전달. 업체 내보내기 일정 공문 수령 |
| 3주차 화요일 | 비밀유지 계약 체결 (법무 표준 양식. 업체 수정 요청 시 금요일로 밀림) |
| 3주차 수요일 | 한지민 과장 데이터 흐름 검토. 서재원 본부장 자체 구축 비용 가정 확인 |
| 3주차 목·금요일 | 실행기 설치 (오세훈 대리, 2인일 목표) |
| 4주차 ~ 5주차 화요일 | 시범 사용과 필수 시험 전체 |
| 5주차 화요일 | 감사 로그 실제 파일 확인 마감 |
| 5주차 수~금요일 | 비교표 작성 |
| 6주차 | 품의 상신과 결재 |

- 계약이나 보안 검토가 밀리면 **시험을 줄이지 않고** 김미경이 최영수 본부장에게 한 주 연장을 메일로 요청함
- 기준을 낮춰 날짜를 맞추지 않음. 기한까지 필수 시험이나 내보내기 확인을 끝내지 못한 후보는 "검증 미완료"로 올리고 도입을 추천하지 않음

## 2. 논의 내용

### 2.1 시범 기간 (2주 대 4주)

- 정우진 팀장이 처음에 2주 시범을 제안함
- 김미경: 지난주 받은 계획서는 4주였고, 3주차 야간 외부망 시나리오와 4주차 Plan 변조 시험이 본부장 보고에서 가장 설득력 있는 부분이라 빠지면 안 된다고 지적
- 결론: 기간은 줄이되 **4주 계획의 시험 항목은 모두 유지**. 설치가 밀려 시험을 못 하면 통과 처리를 미룸

### 2.2 가중치

- 정우진: 현업 만족도 10%가 낮다며 비용에서 5%포인트를 옮기고, "승인 없는 실행 차단"을 필수 조건으로 두자고 제안
- 김미경: 비용을 내리면 최영수 본부장이 바로 문제 삼을 것. 대신 필수 조건 세 개를 따로 빼고 보안 비중을 줄이는 안을 제안
- 결론: 1.3 표대로 확정

### 2.3 실행기 준비 비용

- 시범은 무상이지만 실행기 서버는 회사가 준비해야 함
- 정우진: 오세훈 대리 작업 2인일을 목표로 하고, 업체 권장 사양을 받아 설치·키 등록·Tailscale·mTLS 설정 시간을 나눠 추정
  - 기존 서버 활용안과 신규 서버안 각각의 2주 비용과 월 운영비를 제시
  - 무상 시범이어도 내부 인건비는 비용표에 넣음
  - 사양 확인 전에는 서버 금액을 확정해 적지 않음

### 2.4 자체 구축 3년 비용

- 정우진 기본 가정: 개발 3명 × 6개월(18인월) + 남은 30개월 유지 1명(30인월) = **48인월**, 여기에 서버·보안 검증·교육 비용을 더함
- 기존 "약 4억 원"은 1년 추정치라 단순히 세 배 하지 않고, 인건비 단가와 플랫폼팀 로드맵 6개월 지연 영향을 구분해서 산정
- 김미경: 이 숫자를 서재원 본부장이 미리 인정해야 품의 후 최영수 본부장 앞에서 숫자 다툼이 나지 않음
- 결론: 월요일 초안 → 수요일까지 서재원 본부장에게 가정과 이견을 메일로 확인

### 2.5 일정 오류 수정

- 김미경이 처음에 "다음 주 수요일 계약 체결, 3주차 월요일 설치"로 말했으나, 회의 시점이 2주차 금요일이라 "다음 주"가 곧 3주차여서 순서가 맞지 않음 (정우진 지적)
- 1.7 일정으로 다시 잡음

## 부록: 대화 기록
