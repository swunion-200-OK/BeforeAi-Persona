### 1.7 비상 절차 (실행기 장애 중 긴급 운영 작업)

- 명세에 실행기 장애 때의 오프라인 승인·비상 실행 기능이 없으므로 회사가 별도로 만든다
- 평소 잠가 둔 비상 계정을 제한된 관리 환경에서만 잠깐 연다. 대상 DB, 정확한 쿼리, 예상 영향 행 수, 복구 방법을 실행 전에 기록하고 실행자·검토자·승인 시각·실제 결과를 남긴 뒤 바로 다시 잠근다
- 대표이사 또는 노현숙이 사유와 업무 영향을 확인하고, 쿼리는 해당 DB를 아는 기술 담당 1명이 추가로 검토한다
- 실행기가 멈추기 직전 작업이 반영됐는지 먼저 확인해 같은 쿼리를 두 번 돌리지 않는다 (명세 3.7 롤백은 문서 작업만 해당)
- 비상 실행은 다음 영업일에 함께 검토하고, 시범 실적에서는 빼되 건수와 사유는 결과 보고서에 남긴다

- 제품 구매가 아니라 사고 경로를 어떻게 닫았는지를 약속한다
- 담을 내용: 노트북 운영 DB 쓰기 계정 삭제(완료), 운영 DB 계정 분리 42곳 중 31곳 완료와 남은 11곳 진행 상황, 현재 수동 확인 절차와 한계, 기한까지 실제로 검증한 통제만 구분해서 기재. 못 닫은 경로는 담당자와 완료 예정일을 적는다
- 본 서비스 도입이나 효과가 검증되지 않았으면 검증됐다고 쓰지 않는다
- 27일 CSV는 실제 시범 기록을 변환한 자료로, 출처와 검증 범위를 표시해 근거 자료로 쓸 수 있다

## 2. 논의 내용

### 2.1 사야 하는 이유와 계정 수

- 노현숙: 14계정이면 첫해 477만 원으로 상한까지 23만 원뿐. 승인자만 계정을 줄 수 없는지, CTO가 직접 보면 0원인데 왜 사야 하는지 질문
- 권승재: "CTO가 자리를 비워도 운영 DB 쓰기와 배포가 필요한 승인자의 서명 없이는 실행되지 않게 하고, 누가 승인했는지 기록으로 남기기 위해서." 하루 9건, 1시간 30분, 월 33시간도 비용이라고 답함
- 승인자만 계정을 주면 나머지 개발자가 자기 이름으로 요청할 수 없어 대신 입력하는 병목이 생김 (명세 3.5)
- 처음 제시한 10계정(첫해 약 386만 원)은 비교용이었고, 12명 전원의 운영 작업을 옮기려면 12계정이 필요하다고 정정함

### 2.2 승인이 CTO에게 다시 몰리는 문제

- 노현숙: 고객사 42곳 대부분 담당 1명이라 두 번째 담당이 모두 CTO가 되면 돈을 내고도 똑같다고 지적. "몰린다"의 기준을 숫자로 요구
- 권승재: 담당자 2명 등록(`409 OWNER_MINIMUM`, 3.3)이 매번 2명 서명이라는 뜻은 아니며, 2.2 예시처럼 후보 중 1명이 승인할 수 있음. 다만 `SMALL`에 어떤 규칙이 겹쳐 붙는지는 명세에 없음
- 기준을 1.4 표로 정함. 노현숙이 "HIGH 작업이 적으면"의 최소 건수를 다시 물어 20건, CTO 미참여 10건, CTO 부재일 2일로 확정

### 2.3 실행기 운영과 장애

- 노현숙: 2021년 클라우드 결제 실패로 고객사 2곳이 3시간 멈춘 일을 들어, 서버 장애·결제 연체·CTO 휴가 때 어떻게 되는지 질문
- 권승재: 실행기가 멈추면 제출은 `502 EXECUTOR_UNAVAILABLE`로 막히고 상태는 그대로(4.3). 실행 중이던 작업 처리와 결제 연체 때 제한 범위는 명세에 없음. CTO 노트북으로 쿼리를 돌리는 건 우회라서 기본 대응으로 삼지 않음
- 하준영을 운영 대체 담당으로 제안. 업체에 패치·인증서 갱신·장애 지원 범위와 연락 창구를 서면으로 요청
- 노현숙이 "기다리게 한다"는 답을 고객사 입장에서 받아들일 수 없다고 반박. 권승재가 답이 부족했다고 인정하고 1.7 비상 절차를 제안. 쿼리 검토는 비개발자 확인으로 대신할 수 없다는 조건을 붙임

### 2.4 무료 대안과 데이터 처리

- 노현숙: 대표가 "사고는 DB였으니 무료 도구로 DB만 막으면 되지 않냐"고 물을 것이라며 400만 원 넘게 더 내는 이유를 요구
- 권승재: 무료 도구로 쿼리 통제는 가능. 본 서비스는 배포와 코드 변경까지 승인한 내용과 실행할 내용이 같은지 검증하고 기록함(2.3, 5.1). 다만 설치만으로 남은 DB 접속·배포 경로까지 막아 준다는 내용은 명세에 없음. 무료 도구도 같이 시험할 이유가 있다고 봄
- 노현숙: 고객사 42곳 계약서 비밀유지 조항을 지적. 권승재: 승인 서명 암호화(2.4)는 AI 분석에 들어가는 코드가 밖으로 안 나간다는 보장이 아니고, 4.1에 전송 대상·보관·학습 사용 여부가 없음. 답변 전에는 실제 고객사 코드·운영 데이터를 넣지 않기로 함

### 2.5 연습 데이터와 실제 검증의 구분

- 노현숙: 가짜 데이터만 쓰면 HIGH 20건은 연습이라 "CTO에게 안 몰린다"를 증명할 수 없다고 앞뒤가 맞지 않음을 지적
- 권승재: 두 검증을 섞어 말했다고 인정. 가짜 데이터는 차단 시험에만 쓰고, 도입 판단은 실제 작업 기준으로 하며 못 채우면 유료 전환 보류
- 무료 도구까지 CTO가 동시에 설치하는 안은 거두고 1.6 대안 경로로 정리

### 2.6 숲결리빙 동의와 자사 프로젝트

- 노현숙: 동의가 늦으면 다온예약과 공통 모듈로 시범하자고 제안. 다온예약 DB는 류지아 혼자 보므로 `SAME_DEPT_OTHER`면 DB 모르는 사람이 서명하게 된다고 지적
- 권승재: `SAME_DEPT_OTHER`(2.2)는 같은 부서 다른 사람이라는 조건이지 내용 이해를 보장하지 않음. 남궁혁을 두 번째 검토자 후보로 해 류지아와 쿼리 검토·복구 연습을 먼저 함. 승인 기준표 수정 API(`PUT /admin/approval-matrix`, 3.2)는 있지만 `SMALL`과 담당자 최소 조건을 어디까지 바꿀 수 있는지는 명세에 없음
- 자사 코드라도 다온예약 매장·이용자 데이터가 있어 외부 AI 전송 문제는 별개
- 노현숙이 업체 답변(10일) 후 하루 만에(11일) 고객사 서면 동의를 받는 일정이 맞지 않는다고 지적. 숲결리빙은 18일 동의 시 23일 투입으로 조정

### 2.7 노현숙 계정과 감사 기록

- 노현숙에게 ADMIN을 주면 승인 기준표까지 바꿀 수 있음. EMPLOYEE는 본인 요청 기록만, DEPT_MANAGER는 소속 부서 관리 권한까지 생김 (3.9). 조회 전용 역할이 명세에 없음
- 노현숙: 시범 기간에는 CTO가 뽑아 주는 기록으로 버티고, CSV면 충분하되 27일까지 직접 열어 보겠다고 함. CTO가 만든 파일은 고객사 입장에서 "다온웍스가 만든 표"라 증거가 약하므로 정식 계약 전에는 제품에서 내려받은 파일이어야 한다고 요구
- 권승재: 동의. 제품에서 받은 파일이라도 위변조가 없다는 보장은 아니므로 승인·실행 기록과 연결해서 보여 줘야 한다고 보탬

### 2.8 필수 조건 줄이기

- 권승재가 처음에 낸 필수 항목이 10개 가까이 되자, 노현숙이 28명·13계정 고객이 필수를 열 개 넘게 보내면 답을 대충 받을 수 있다며 5개 안으로 줄이자고 함
- 1.3의 5개로 묶고, 나머지(실행기 운영 지원, 접속 정보 보관 방식, 결제 연체 시 제한, 시범 비용 부담, 종료 후 데이터 반환)는 질문·자료 요청으로 돌림. 일괄 등록과 보고서 자동 생성은 희망 사항

### 2.9 웹 서비스 위치와 Tailscale

- 노현숙: 웹 화면은 업체 서버에 있고 실행기만 우리 클라우드에 두는 건지, 업체 서버가 우리 쪽에 들어오는 비용·위험이 있는지 질문
- 권승재: 명세 1.1과 5장에는 웹 서비스 서버가 Tailscale 내부망으로 mTLS 인증을 거쳐 실행기를 호출한다고만 있고, 웹 서비스를 업체가 운영하는지 우리가 설치하는지는 없음. 업체 서버를 연결한다면 실행기 API에만 접근하고 고객사 DB나 다른 장비로 갈 길이 없는지 확인해야 함. 구성·접근 권한·차단 책임·비용을 10일 회신 항목에 넣음
- 11. 5.(목) 정오 비용 자료에서 업체 답변이 필요한 부분은 미확정으로 표시하고, 그 비용을 빼고 상한 안이라고 보고하지 않음

## 4. 남은 질문
