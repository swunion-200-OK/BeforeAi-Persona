2. 관련

   - 나. 귀사 보완 설명 메일 (2026. 11. 7.(토), 관련 가.의 우려 3번·5번에 대한 참고 설명)
   - 다. 당사 내부 회의 「실행기 성격·Tailscale 재평가」 (2026. 11. 9.(월))

3. 당사는 관련 가. 공문을 발송한 뒤, 귀사로부터 서면 회신(관련 가. 7항 기한 2026. 11. 10.(화)) 전에 참고용으로 두 가지 보완 설명(관련 나.)을 수령하였습니다. 본 공문은 그 설명을 반영해 당사의 검토 조건을 일부 조정하고, 설명을 서면으로 확정하기 위해 추가로 확인할 사항을 전달하는 것입니다. 관련 가. 공문의 필수 조건 5개, 비용 상한(첫해 VAT 별도 500만 원·월 40만 원 이내), 13계정 기준, 시범 통과 기준은 **변경하지 않습니다.**

4. 보완 설명에 대한 당사의 이해

   **가. 실행기의 성격 (관련 나. 보완 설명 1)**

   당사는 귀사 설명을 아래와 같이 이해하였습니다. 아래 이해가 귀사 설명과 다르면 2026. 11. 10.(화) 서면 회신에서 바로잡아 주십시오.

   | 번호 | 당사가 이해한 실행기의 성격 | 명세 근거 |
   | --- | --- | --- |
   | 1 | 실행기는 운영 작업을 대신 수행하는 별도의 무거운 인프라 러너가 아니라, Plan 해시를 스스로 생성하고 Ed25519 서명과 nonce를 검증하는 "서명 검증기"임 | 2.3, 5.1 |
   | 2 | 승인 envelope은 비대칭키 기반 종단간 암호화(E2EE)로 전달되어 실행기 공개키로만 복호화되며, 웹 서비스는 열람할 수 없음(전달만 함) | 2.4, 4.5 |
   | 3 | 검증 6단계를 모두 통과한 경우에만 실행기가 웹쉘 세션을 열어 로컬에서 작업을 수행함. 즉 "검증·복호화·웹쉘 로컬 실행" 컴포넌트임 | 5.1, 5장 |

   **나. 실제 운영 배포의 망 구성 (관련 나. 보완 설명 2)**

   당사는 귀사 설명을 아래와 같이 이해하였습니다.

   | 번호 | 당사가 이해한 운영 배포 구성 | 명세 근거 |
   | --- | --- | --- |
   | 1 | 명세의 Tailscale은 개발·테스트 단계의 임시 구성이며, 운영 고정 요구 사항이 아님 | 1.1, 5장 |
   | 2 | 실제 운영 배포는 고객사 내부망 연결(웹 서비스↔실행기 mTLS)로 이루어짐 | 1.1, 5장 |
   | 3 | 내부망으로 판별할 대역은 관리자가 설정함 | 1.1 |

5. 위 설명 반영에 따른 검토 조건 조정

   아래 조정은 관련 다. 당사 내부 회의 결과이며, 2026. 11. 10.(화) 귀사 서면 회신으로 확정됩니다. 보완 설명은 참고용 메일이므로 서면 회신 전까지는 "업체 설명 기준"으로만 취급하며, 필수 조건의 "충족" 근거로 보지 않습니다.

   **가. 완화된 우려 (관련 가. 5항 다. 우려표 기준)**

   | 번호 | 관련 가. 우려 | 조정 후 | 조정 사유 |
   | --- | --- | --- | --- |
   | 4 | Tailscale 접속을 내부망으로 판별 → 재택 시 외부망 제한(4.4)이 적용되지 않음 | **완화**. "재택에서 Tailscale만으로 자동 내부망이 되는 전제"는 운영 배포가 내부망 mTLS + 관리자 대역 설정이면 사라짐. 아래 6항 가. 1번·2번 서면 확인을 조건으로 함 | 운영 배포가 개발용 Tailscale에 의존하지 않음(4항 나.) |
   | 3 | 웹 서비스 운영 주체와 연결 구성 | **재서술**. "당사 Tailscale 내부망에 상시 연결" 전제에서 "운영은 내부망 mTLS, 구성·운영 주체는 미확인"으로 변경. 확인 요청은 유지 | 상시 Tailscale 연결 전제 제거(4항 나.) |

   **나. 유지되는 우려**

   | 번호 | 관련 가. 우려 | 유지 사유 |
   | --- | --- | --- |
   | 5 | 실행기 1대에 고객사 42곳 접속 정보 집중 | 실행기가 경량 컴포넌트라는 사실과 접속 정보 집중 문제는 별개임. 프로젝트별 격리 방식 확인 필요(관련 가. 7항 5번 유지) |
   | - | 단일 컴포넌트 장애 시 그 시점 실행 중단 (신규) | 실행기가 경량이어도 단일 구성이면 장애 시 해당 시점 운영 작업이 중단됨. `502 EXECUTOR_UNAVAILABLE`(4.3)은 "승인 없는 실행"을 막을 뿐 가용성을 보장하지 않음. 이 우려는 **"서버 증설"이 아니라 "페일오버·다중화"** 관점에서 확인함(아래 6항 나.) |

   **다. 운영 부담 평가 기준 변경 (관련 가. 5항 나. 필수 조건 4번)**

   | 항목 | 관련 가. 기준 | 조정 후 |
   | --- | --- | --- |
   | 필수 조건 4 (운영 가능성) | "인프라 전담 인력 없이 실행기 1대(서버)를 운영할 수 있을 것" | "인프라 전담 인력 없이 **경량 컴포넌트**를 운영할 수 있고, **단일 장애 시 페일오버·다중화로 대응 가능 여부**를 확인할 수 있을 것". 시범 시 CTO 운영 시간 주 1시간 이내 기준은 유지 |

   - 비용표의 실행기 월 약 9만 원 추정은 유지합니다. 실행기가 경량 컴포넌트라도 구동 환경 비용이 발생하며, 성격 재정의가 단가 인하 사유는 아닙니다.
   - 본 조정으로 비용 상한, 13계정 기준, CTO 승인 참여율 50% 이하, 시범 통과 기준(붙임 2, 관련 가.)은 변경되지 않습니다.

6. 추가 확인 요청

   아래는 보완 설명을 당사 환경에 적용하기 위한 확인 사항입니다. 가능하면 2026. 11. 10.(화) 서면 회신에 포함해 주시고, 운영 문서 관련 항목(나.)은 2026. 11. 24.(화) 자료 제출 시 포함해도 됩니다.

   **가. 내부망 대역 설정과 재택(외부망) 규칙 — 필수 확인 (2026. 11. 10.(화))**

   | 번호 | 확인 요청 | 당사 사정 |
   | --- | --- | --- |
   | 1 | 내부망으로 판별할 대역을 관리자가 직접 설정하는 기능(API·화면)이 있는지. 당사 사무실 고정 IP 1개를 내부망으로 지정할 수 있는지 | 당사는 회사 VPN이 없고 사무실 고정 IP가 1개임 |
   | 2 | 내부망 대역 밖(재택)에서 외부망 규칙(4.4의 DATA_WRITE·DEPLOY 승인 차단, `INTERNAL_NETWORK_ONLY`)이 그대로 적용되는지 | 개발자 화·목 재택. 재택일 운영 작업은 사무실 접속 또는 당사 비상 절차로 처리할 예정 |
   | 3 | 개발용 Tailscale 구성과 운영용 내부망 mTLS 구성의 전환 절차와, 시범(2026. 11. 16.~27.) 중 어느 구성으로 설치하는지 | 시범 설치는 2026. 11. 12.(목)~13.(금) |

   **나. 가용성(페일오버·다중화) — 필수 요청 (운영 문서, 2026. 11. 24.(화))**

   | 번호 | 요청 내용 |
   | --- | --- |
   | 1 | 실행기 컴포넌트 장애 시 자동으로 넘겨받는 대기 컴포넌트(페일오버) 또는 다중화 구성이 가능한지 |
   | 2 | 다중화 구성 시 서명 검증·복호화에 쓰는 실행기 키 쌍의 공유·분리 방식 |
   | 3 | 다중화 구성에서도 nonce 1회 소진(2.4, 5.1)이 컴포넌트 간에 보장되어, 동일 승인이 둘 이상의 컴포넌트에서 각각 실행되지 않는지 |
   | 4 | 소규모 조직용 관리형 실행기 옵션 유무. 있을 경우 고객사 접속 정보 보관 주체와 추가 비용 |
