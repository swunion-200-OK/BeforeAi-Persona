### 1.5 성공·중단 기준

| 구분 | 기준 | 판정 |
| --- | --- | --- |
| hard fail | 승인 없는 실행 1건 | 파일럿 즉시 중단, 당일 VRM 보고. 원인 조치와 재개 승인 전 재가동 금지 |
| hard fail | 변조된 Plan 실행 (5.1 `PLAN_HASH_MISMATCH` 거부 실패) | 같음 |
| hard fail | 소진된 envelope 재사용 성공 (5.1 `NONCE_ALREADY_USED` 거부 실패) | 같음 |
| hard fail | 참여자 노트북에서 유효한 랩 스테이징 키 발견 | 같음 |
| 안전 기준 | 킬 스위치 요청부터 `KILLED`까지 10초 초과 (4.6) | 해당 실행 시험 중단, 확대 불가 판정 |
| 운영 기준 | DEPLOY 승인 대기 중앙값 1시간 초과 (근무 시간 기준) | 한국 확대 보류 |

| 목표 | LOW 요청~실행 중앙값 5분 이내, DEPLOY 승인 대기 중앙값 30분 이내 | 미달 시 개선 요청 |
| 목표 | 설문 "계속 쓰고 싶다" 70% 이상 | 미달 시 개선 요청. 안전 기준 통과만으로 전체 성공으로 쓰지 않음 |

- 성공 증빙에는 5.1 거부 로그뿐 아니라 **노트북 직접 실행 경로가 실제로 막힌 증빙**을 붙임

### 1.6 정식 도입 조건

**공통 (한국 확대·글로벌 모두)**

- DPA, 데이터 흐름과 저장 위치(웹 서비스·DB·감사 로그·백업, AI 분석 호출 경로)
- 본사 MSA 수용, 재무 검토(최근 3년 재무제표), USD 송장, 사이버 보험 USD 5M
- SOC 2·ISO 27001이 없을 때의 보완 패키지(SOC 2 Type I 일정 확약 + 외부 모의해킹 보고서)는 Tier 1 기준을 바꾸는 것이 아니라 **Global VRM 서면 예외 승인 대상**. 서면 승인 없이는 한국 확대도 불가

**한국 법인 확대 필수 (4개, acceptance test로 확인)**

| 번호 | 조건 | 명세 상황 |
| --- | --- | --- |
| 1 | Okta SSO (SAML 또는 OIDC) | 3.1은 사번·비밀번호 로그인만 있음 |
| 2 | 감사 로그 파일 내보내기와 Splunk 전송 (전송 지연·누락 복구 포함) | 3.9 `GET /audit-logs`는 검색만 |
| 3 | ServiceNow CHG 번호와 실행 가능 시간 창을 Plan 해시 대상에 넣고, **실행기가 실행 직전에 CHG 승인 유효성과 실행 창을 검사**해 벗어나면 거부하고 `failedChecks`에 사유를 남김 | 2.1에 외부 참조 없음, 2.3 해시 대상에 없음, 2.4 서명 만료 없음, 5.1 검증 항목에 없음 |
| 4 | 실행기의 GitHub Enterprise Cloud 접근 방식(자격 종류, 쓰는 브랜치) 서면 공개, 보호 브랜치와 required review를 우회하지 않는다는 시험 통과 | 명세에 정의 없음 |

- SCIM 2.0: 한국 확대 후 90일 안에 납품. 업체가 납품일과 acceptance test를 서면 확약하고 Global VRM이 그동안의 수동 통제를 승인해야 함. 90일을 넘기면 자동 연장 없이 추가 사용자 확대를 멈추고 예외 지속 여부를 재심사
- 실행기 이중화: 사내 랩 범위의 한국 확대에서는 우선순위를 낮추되, 4.3 `502 EXECUTOR_UNAVAILABLE` 때 상태 유지와 복구 절차·복구 시간은 파일럿에서 검증. 고객사 환경은 별도 승인 때 가용성 기준을 다시 걺
- 비용: 업체 견적을 라이선스 포함분, 별도 개발비, 실행기 비용으로 나눠 받음. 연 USD 50,000을 넘으면 APAC CFO 결재가 추가되므로 차유나가 Priya 통해 일정을 미리 확인. Tier 1 본사 승인은 금액과 관계없이 필요

**글로벌 확대 추가 조건**

- SOC 2 Type II
- 영어 UI·영어 오류 메시지 (1.2 `message` 예시가 한국어)
- 실행기 이중화
- follow-the-sun 실증: 1.1 지역 사무소 대역 판별, 4.4 `approval-context`에서 DEPLOY가 `INTERNAL_NETWORK_ONLY`로 막히는 조건, 2.2 `PROJECT_OWNER` 승인 자격을 함께 확인
