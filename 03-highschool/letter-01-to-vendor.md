5. 요청 사항

   모든 항목은 붙임 3 양식에 따라 **현재 가능 / 개발 필요 / 제공 불가 / 제공 날짜** 네 칸으로 회신해 주시기 바랍니다. 현재 API로 확인할 수 있는 항목과 새로 요청하는 기능을 구분하였습니다.

   **가. 필수 요청 (2026. 11. 13.(금)까지 회신. 1단계 시범에서 실제 동작을 확인)**

   | 번호 | 구분 | 요청 기능 | 요청 내용 |
   | --- | --- | --- | --- |
   | 1 | 현재 API 검증 | 학생 승인 배제 | `PUT /admin/approval-matrix`·`GET /approval-matrix`로 학생의 본인 승인과 학생 간 승인을 모두 배제하는 설정 방법. 학생 계정이 `POST /requests/{requestId}/approvals`를 호출하면 `403 NOT_APPROVER`가 나는 증빙 |
   | 2 | 현재 API 검증 + 개발 필요 시 신규 | 위험 작업 교사 2인 서명 강제 | DB·DATA_WRITE·DEPLOY에 서로 다른 교사 2명의 서명을 요구하고, 서명 1개로 실행을 요청하면 실행기가 `MISSING_REQUIRED_APPROVER`로 거부하는 증빙. 현재 불가하면 승인 기준표 규칙 예: `{ "rule": "PROJECT_OWNER", "count": 2, "distinctApprovers": true, "excludeRequester": true }` 형태 지원 일정 |
   | 3 | 현재 API 검증 | 키 폐기·담당자 교체 | `DELETE /admin/signing-keys/{keyId}`, `PATCH /admin/users/{userId}`(비활성화), `PUT /projects/{projectId}/owners`를 함께 쓸 때 폐기된 키로 실행이 막히고(`KEY_NOT_REGISTERED`) 영향받는 승인 대기 요청이 `REAPPROVAL_REQUIRED`로 바뀌는 절차와 운영안 |
   | 4 | 신규 | 승인 자격 표시 | 계정에 승인 가능 여부를 표시하는 값 (예: `PATCH /admin/users/{userId}`에 `"approvalEligible": false`). 승인 불가 계정은 승인 후보(`candidates`)에서 제외되고 실행기 로컬 정책에도 반영 |
   | 5 | 신규 | 감사 로그 파일 내보내기·인쇄 | `GET /audit-logs`의 검색 조건을 그대로 적용한 내보내기 (예: `GET /audit-logs/export?format=csv|xlsx&from=&to=&projectId=`). 승인자, 서명 키 ID, 접속 환경, IP, 실행 결과 포함, 한글 정상 표시. 인쇄용 화면과 출력 견본 제출 |
   | 6 | 신규 | 조회 전용 권한 | 감사 대응 담당이 감사 로그와 대시보드를 **조회만** 할 수 있는 역할 (예: `AUDITOR`). 계정·정책·키 변경 권한 없음. 학생 이름 가림 옵션 포함 |
   | 7 | 현재 API 검증 | 가명 계정 | 로그인 ID와 표시 이름에 학번·실명 대신 임의 ID와 가명을 쓸 수 있는지 (`POST /admin/users`, `POST /auth/login`, 2.1 `requester.name`, 4.8 `actor.name`) |
   | 8 | 운영 방안 | 수업 밖 화면 감시 없는 승인 요청 인지 | 교사가 승인 대기 목록(`GET /approvals/pending`)을 계속 열어 두지 않아도 승인 요청을 알 수 있는 방안. Slack 없이 가능한 방법 |
