## 1. 결정 사항

### 1.1 결론: 보류 유지 (일부 보류 사유만 조정)

- BeforeAI는 **여전히 보류**. 보완 설명 2건으로 보류가 풀리지 않음
- 업체 설명은 "문서 설명"이고, 보류 해제는 1월 7일 전후 업체 사무실 시험과 11. 27.·12. 11. 제출 자료로 판단한다는 `meeting-01` 원칙은 그대로 둠 (노재석: "설명으로 내려가는 사유와, 시험으로 확인할 사유를 섞지 맙시다")
- 보완 설명으로 **오해였던 부분은 정정**하되, 설명만으로 자동 해소되지 않는 사유는 그대로 유지함

### 1.2 보완 설명 1 — 실행기의 성격 (조정)

업체 설명 요지: 실행기는 무거운 별도 인프라 러너가 아니라 경량 컴포넌트이며 (a) Plan 해시를 자체 생성하고 Ed25519 서명·nonce를 검증하는 "서명 검증기", (b) 승인 envelope을 비대칭키 종단간 암호화(E2EE)로 받아 실행기 공개키로만 복호화(웹 서비스는 열지 못함), (c) 검증 6단계를 통과하면 웹쉘 세션으로 로컬 작업을 수행하는 구조.

| 항목 | 1차 검토 때 전제 | 보완 설명 반영 후 |
| --- | --- | --- |
| 실행기 성격 | "무거운 별도 서버 인프라 러너"로 읽고 서버 2대 이중화·대형 사양을 전제 | 경량 서명 검증기 + 복호화 + 웹쉘 수행 컴포넌트로 재서술. "서버 2대"가 아니라 **컴포넌트 다중화·페일오버**로 이중화 요건을 다시 씀 |
| 복호화 주체 | (2.4, 4.5로 이미 이해) 웹 서비스는 envelope을 열지 못함 | 재확인. "웹 서비스가 뚫려도 실행기 공개키 없이는 복호화 불가"라는 강점은 그대로 유지 |
| 웹쉘 세션 | 운영 서버에 셸이 열리는 구조라는 우려(10.4의 16번, 1차 공문 우려 8번) | **우려 유지.** 경량 컴포넌트라는 점과, 운영 서버에 셸이 열린다는 점은 별개. 명령 범위 제한과 세션 기록 요구는 그대로 둠 |

- 조정: 서버 사양·이중화 요구를 "서버 2대"가 아니라 "컴포넌트 다중화·페일오버"로 다시 적음. 1차 공문 제출 자료 5번(서버 최소 사양·이중화 지원 방식)도 이 표현으로 바꿔 회신받음
- 유지: 웹쉘 세션의 명령 범위 제한과 세션 기록 요구 (노재석: "경량이라 다행인 거랑, 운영 서버에 셸이 열리는 건 다른 얘깁니다")

### 1.3 보완 설명 2 — Tailscale (조정)

업체 설명 요지: Tailscale은 개발·테스트 단계의 임시 구성이며, 운영 배포는 고객사(시청) 내부망(행정망) 연결로 하고 웹 서비스↔실행기는 mTLS, 내부망 대역은 관리자가 설정. 외부 조정 서버는 운영 배포에 필요 없음.

| 1차 보류 사유(공문 보류 사유 1번·우려 9번) | 보완 설명 반영 후 |
| --- | --- |
| "Tailscale 조정 서버가 인터넷에 있어 망분리 환경에서 못 씀" | 개발·test용 구성이고, 운영 배포는 행정망 내부 설치 + mTLS, 외부 조정 서버 불요라는 설명으로 **상당 부분 해소 방향**. 단 시험에서 실제로 외부 통신이 없는지 확인해야 최종 해소 |
| "접속 환경 판별 대역(100.64.0.0/10)이 기본 내부망" | 내부망 대역을 관리자가 설정한다는 설명. 행정망 대역만 내부로 두는 설정이 되는지 시험으로 확인 |

- 조정: "Tailscale 불가"를 보류 사유의 전부로 적지 않고, "운영 배포는 행정망 내부 mTLS, 외부 조정 서버 불요(업체 설명)"로 다시 적되 "인터넷 차단 상태 동작과 외부 통신 없음을 시험으로 확인"을 조건으로 남김
- 유지: 1차 공문 제출 자료 2번(행정망 내부 설치 구성도와 전체 통신 흐름 — 설치·라이선스 인증·알림·업데이트 포함)은 그대로 받음. 라이선스 인증이나 업데이트가 외부 통신을 요구하면 그 부분은 다시 보류 사유가 됨

### 1.4 보완 설명으로 **해소되지 않는** 보류·필수 사유 (그대로 유지)

| 번호 | 유지 사유 | 근거 | 왜 보완 설명으로 안 풀리는지 |
| --- | --- | --- | --- |
| 1 | 검증필 암호모듈(KCMVP) 적용 | 2.4, 4.5, 5장 | 실행기가 경량이든 Tailscale을 빼든, 서명·암호화·mTLS에 쓰는 암호모듈의 검증 여부와는 무관. 제품명·버전·검증 증빙으로만 확인 |
| 2 | 제품 인증(CC인증 또는 보안기능 확인서 등) | 명세 밖 | 구조 설명이 아니라 인증 접수·보유 증빙의 문제 |
| 3 | 공무원 승인권자 한정 | 1.3, 2.2 | Role에 소속 구분이 없는 건 그대로. 외주 인력 키 제출·등록 차단 포함 |
| 4 | 외부망 승인 전면 차단 | 1.1, 3.6, 4.4 | 운영 배포가 내부망이라는 설명과 별개로, 정책으로 외부망 기능을 끌 수 있어야 함 |
| 5 | 감사 로그 2년 보관·파일 내보내기·위변조 방지 | 3.9, 4.8 | 조회만 있는 상태 그대로 |
| 6 | AI 분석 위치와 외부 전송 없는 구성 | 4.1 | 보완 설명 2건 어디에도 분석 위치가 없음 |
| 7 | 웹쉘 세션 명령 범위 제한·세션 기록 | 5.1 | 1.2에서 유지로 정함 |
| 8 | 승인자 본인 확인과 개인키 보호·회수 | 2.4, 3.1 | 구조 설명과 무관 |

- 노재석: "둘(실행기 성격, Tailscale)은 받아서 내려 주겠습니다. 나머지는 그대로입니다. 보완 설명으로 인증이 생기는 건 아니니까요."

### 1.5 다음 공문 반영

- 1차 공문(스마트도시정보과-4127) 후속으로, 결론은 "보류 유지"로 하되 보완 설명을 반영해 보류 사유 1번(행정망 설치·통신 흐름)과 우려 8·9번(웹쉘·판별 대역)을 다시 정리한 공문을 보냄
- 실행기 성격 재정의(경량 서명 검증기 + E2EE 복호화 + 웹쉘 수행)와 Tailscale 성격(개발 test용 / 운영 배포 행정망 내부 mTLS)을 공문에 그대로 적어 "오해 정정"을 기록으로 남김
- 남는 필수 보완 요구(1.4의 8개)는 다시 정리해 붙임. 1차·2차 제출 기한(11. 27., 12. 11.)과 시험 일정(1. 7. 전후)은 바꾸지 않음
- 서버 사양·이중화 표현을 "컴포넌트 다중화·페일오버"로 바꿔 회신 요청

### 1.6 공정성

- 이 공문도 비교 업체 2곳에 보낸 공통 기준표를 바꾸지 않음. 보완 설명 반영은 BeforeAI용 확인 자료(붙임 2 성격)에만 반영하고, 공통 기준표(붙임 1)는 그대로 둠 (배선영: "한 곳 설명 때문에 공통 기준표를 바꾸면 그게 특혜 시비예요")
- 보완 설명을 받았다고 BeforeAI만 재검토 일정을 앞당기지 않음

## 2. 논의 내용

### 2.1 "설명"과 "확인"의 구분

- 배선영: 업체가 보완 설명을 보내왔으니 보류를 조금이라도 내려야 하는 것 아니냐, 과장이 "진척"을 물을 것이라고 함
- 노재석: 설명으로 내려갈 사유(오해였던 것)와 시험·증빙으로만 확인할 사유를 섞으면 나중에 감사에서 "업체 말만 믿고 풀었다"가 된다고 선을 그음
- 결론: 실행기 성격·Tailscale은 "오해 정정"으로 조정하되, 외부 통신 없음과 판별 대역 설정은 1. 7. 시험으로 확인한다는 조건을 남김

### 2.2 웹쉘 세션 (이견 없이 유지)

- 배선영: 업체가 "무거운 서버가 아니라 경량"이라고 했으니 웹쉘 걱정도 줄어든 것 아니냐고 물음
- 노재석: 컴포넌트가 가볍다는 것과 운영 서버에 셸이 열린다는 것은 다른 문제라고 함. 명령 범위 제한과 세션 기록은 그대로 요구
- 결론: 1차 공문 우려 8번(웹쉘) 유지

### 2.3 이중화 표현 (조정)

- 노재석: 1차에 "실행기 서버 2대"로 적은 것은 업체 구조를 무겁게 오해한 것이라며, "컴포넌트 다중화·페일오버"로 바꾸자고 함. 다만 nonce 소진·키 폐기·정책이 다중화된 컴포넌트에 일관되게 반영되는지는 그대로 확인해야 한다고 덧붙임
- 배선영: 예산 산정에서 "서버 신규 2대"로 잡아 둔 추경 산정안은 어떻게 되냐고 물음
- 노재석: 산정은 1월 15일 확인 결과로 조정하기로 이미 정했으니, 지금 산정안을 고치지는 말고 업체 회신(최소 사양·다중화 방식)을 받아 보자고 함
- 결론: 공문 표현만 "컴포넌트 다중화·페일오버"로 바꾸고, 추경 산정안은 1. 15.에 조정

### 2.4 Tailscale 조정과 남는 통신 (조정 + 조건)

- 노재석: 운영 배포가 행정망 내부 mTLS라는 설명은 받되, 설치·라이선스 인증·알림·업데이트까지 외부 통신이 없는지가 핵심이라고 함. 라이선스 인증이 외부 서버로 나가면 결국 같은 문제라고 지적
- 배선영: 그럼 공문에 "Tailscale 해소"라고 단정해도 되냐고 물음
- 노재석: "해소"가 아니라 "업체 설명대로면 상당 부분 해소되나 외부 통신 없음을 시험으로 확인"으로 적자고 함
- 결론: 1.3대로

### 2.5 인증·암호모듈은 그대로 (이견 없음)

- 배선영: 보완 설명에 암호모듈이나 인증 이야기가 있었냐고 물음
- 노재석: 둘 다 구조 설명이라 암호모듈·인증은 한 줄도 없었다고 함. KCMVP·CC/보안기능 확인서·공무원 승인권자 한정·외부망 차단·감사 로그·AI 분석 위치는 그대로 남는다고 확인
- 결론: 1.4대로 유지
